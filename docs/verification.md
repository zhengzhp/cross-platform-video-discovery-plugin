# 验证规范

验证命令以 [package.json](../package.json) 为准；当前只有骨架检查，没有业务测试框架或 npm test。

## 1. 骨架与静态检查

Node.js 22.13+，推荐 24；在项目根目录执行：

```sh
npm install
npm run typecheck
npm run build
node --check scripts/clean.mjs
npm pack --dry-run --ignore-scripts
npm run clean
```

- 安装依赖会访问 registry，并生成锁文件；首次安装后应保留锁文件。已有锁文件时，干净安装优先使用 npm ci。
- 当前工作区未安装依赖，骨架创建时使用已有本地编译器验证；以上标准安装流程尚未在本项目执行，不能当作历史测试结果。
- 通过标准：命令成功、产物包含预期空入口，打包预览无数据库/profile/凭据。clean 只删除 dist。
- 构建只能证明 TypeScript 模块可编译，不能证明 Pi/DSH 加载或 SQLite 可用。

仅修改文档时，至少检查相对链接、引用命令、当前状态及计划范围的一致性；无需因此执行真实网络抓取。

## 2. 后续离线业务测试（尚未实现）

开发相关逻辑时增加真实用例和测试脚本，不用空测试占位：

- 单元：链接规范化、去重、硬条件未知、排序解释、反馈影响范围和撤销重算；自定义平台的标识/域名/模板/规则校验，确保新增来源不依赖固定四项白名单，拒绝任意脚本执行配置。
- 集成：临时 SQLite 中的持久化、跨进程锁、批次引用、事务一致性与异常恢复。
- 浏览器执行层：使用可控假执行器验证命令参数、调用上限、失败隔离、超时、取消及资源清理，不能默认调用登录浏览器。
- 任何默认测试均不得依赖密钥、真实账户或外部平台；通过标准是相关断言实际运行并通过。

## 3. 宿主与来源冒烟（尚未执行）

业务实现后主动执行，发布前目标为一次 15～30 分钟冒烟，不建设长期测试门槛：

- Pi 与 DSH 分别加载，展示真实具体视频链接和来源状态。
- 同数据库反馈可跨宿主读取与撤销，偏好恢复；同用户查找锁生效，结束/取消后能再次查找。
- 超时、整轮截止时间和调用上限生效，登录/验证码不绕过，不执行平台写操作。
- 分开记录启动、导航/等待、提取、核验和模型调用耗时；不预设未实测的速度承诺。

时间盒不是跳过阻断问题的理由。宿主或来源未验证时明确标记，不宣称双宿主/四平台全部可用。

## 4. 结果记录与交付

在 [状态文档](status.md) 记录关键检查的环境/版本、命令或方法、结果及未验证范围；失败保留原因和下一步，不存完整日志、页面内容或凭据。新增脚本、测试或 CI 时同步本文件与 README。

最终交付区分：静态检查通过、离线业务测试通过、真实冒烟通过。不得互相替代。
