# 开发步骤拆分

本文将 [权威开发计划](development-plan.md) 拆分为可执行、可验证的小步骤，不替代其产品范围和运行边界。实际完成情况以 [项目状态](status.md) 为准，检查要求见 [验证规范](verification.md)。

按单人／单 Agent 顺序执行，不设多人分工和交接。用户已授权产品开发；本次只优化规范，不启动后续业务或宿主安装。实际步骤状态统一在 [项目状态](status.md) 维护，本文只定义目标、依赖和验收。

## 1. 规划依据与交付边界

规划基于 TypeScript/ESM、共享核心、薄宿主适配和统一 agent-browser，不改变产品范围。环境与能力现状查状态文档，不把最初骨架快照当成当前事实。

分两次交付：

1. **Pi 单来源试用版**：兴趣 → 有限页面查找 → 去重排序 → 保存并展示 → 反馈与撤销 → 再找一轮。
2. **双宿主试用版**：DSH 薄适配，共享数据库、跨宿主反馈与查找互斥验证。

不等待四个平台全部可用，外部搜索可在页面闭环后接入。首版不开发自定义平台配置、独立 UI、定时任务或第二套浏览器后端；平台标识仍须可扩展。

### 每次执行批次的规则

- 开始前写明本批目标、非目标、原整体目标、验收及预计涉及文件；集中完成一个可验证切片，不因切片完成自动结束已授权的整体任务。
- 状态区分进行中、阻塞、暂停、本批完成与整体完成。部分实现按“已实现、未验收项”登记，不标成完整步骤完成。
- 缺少授权或外部运行条件时记录阻断点，继续可独立验证的授权工作；若无法继续或受执行环境限制，明确停止原因、剩余步骤与下一次入口，不删掉原待办或降低验收。
- 范围变化保留原目标与原因，更新完整计划；只有整体承诺和对应验收全部落实，才能称整体完成。

### 前置兼容性核对（嵌入相关步骤，不新增阶段）

在继续步骤 3、6～9 前，先只读核对 Pi/DSH 实际版本、加载方式、工具返回与取消接口、宿主 Node/SQLite 和 agent-browser CLI 能力。可获得的文档、类型与版本证据先检查；真实加载、专用浏览器运行或用户级配置需要相应操作授权。未获得的环境条件记入状态，不让未知兼容性静默传到最后冒烟。

## 2. 阶段 A：工程基础与共享核心

### 步骤 1：建立可复现开发环境

- 工作：确认 Node.js 22.13+（推荐 24）；安装开发依赖并保留锁文件；按需补充 Node 类型；建立离线测试脚本并同步说明。已有锁文件后才能使用 npm ci。
- 产物：package.json、锁文件、测试配置及首批真实测试；必要时调整 TypeScript 配置。
- 依赖：获得相应开发与依赖安装授权。
- 验收：项目内安装后 npm run typecheck、npm run build 通过；新增测试脚本实际运行断言；按验证规范检查打包内容，无数据库、profile 或凭据。

### 步骤 2：定义共享业务契约

- 工作：定义兴趣、候选视频、查询计划、批次、反馈、来源状态与运行预算；明确全局唯一批次 ID、编号绑定、取消和错误表达。
- 产物：src/core/ 下共享类型及契约测试；按需确定核心与浏览器、平台、宿主的小边界。
- 依赖：步骤 1。
- 验收：合成数据覆盖必填字段、未知字段和批次引用；新增平台不依赖固定四项枚举；接口无宿主耦合或循环依赖。校验/错误/重试责任符合 [架构契约](architecture.md)，契约增加时同步调用端和真实断言。

### 步骤 3：实现 SQLite 存储

- 工作：前置核对 node:sqlite 运行条件，真实宿主可用性按相应授权验证；实现兴趣、视频、批次、反馈、交付/已看记录的 schema、初始化、唯一键、事务与分步保存。区分保存与交付确认，旧数据不能无证据升级为已交付。
- 产物：src/core/ 下存储实现和临时数据库集成测试。
- 依赖：步骤 2。
- 验收：重启后可读取；重复视频不重复入库；事务失败回滚；批次结果顺序稳定；数据库不落到仓库。保存成功但交付失败/取消不误计历史，重复/部分交付确认幂等且不重排编号；迁移不破坏原始反馈，未确认旧记录不视为已交付。离线存储与真实宿主验收分别记录。

### 步骤 4：实现跨进程查找锁

- 工作：同用户整轮查找互斥，忙时明确返回；正常结束、取消、失败释放；异常退出可有界恢复，不依赖单进程内存锁。
- 产物：src/core/ 下锁实现和多进程集成测试。
- 依赖：步骤 3。
- 验收：两个独立进程竞争，仅一个查找成功启动；取消和异常退出后可安全再次获取；等待有界，恢复不会误释放仍有效的其他任务锁。覆盖 PID 复用/挂起活进程、资源退出前不提前释放及清理故障；完整运行验收依赖步骤 6、8，不以基础锁单测替代。

### 步骤 5：实现兴趣、去重、排序与反馈

- 工作：链接规范化；按同平台 ID/链接去重；明确排除、已看过滤、作者分散和排序解释；反馈保存、撤销、事务内偏好重算。
- 产物：src/core/ 下业务模块与离线用例。
- 依赖：步骤 2、3。
- 验收：覆盖缺失元数据、硬条件未知、重复候选、歧义编号、反馈影响范围与撤销；“质量不好”默认只影响视频；无原因负反馈不自动降低整个主题；撤销后由有效反馈正确恢复偏好。

## 3. 阶段 B：页面发现与 Pi 最小闭环

### 步骤 6：实现受限浏览器执行层

- 工作：src/browser/ 封装 agent-browser CLI；专用会话/profile；校验参数，限制输出、超时、重试与调用量；接入取消、子进程生命周期和资源清理。
- 产物：CLI 执行封装、可控假执行器与离线测试。
- 依赖：步骤 1、2；实际 CLI 能力以实现时版本文档为准。
- 验收：假执行器验证参数、失败、超时、取消、输出上限及清理；遵守共享截止时间，不叠加查询重试，确认本任务资源退出并覆盖清理故障；不用 shell 拼接不可信输入，不清理外部资源或删除专用 profile 持久文件；不提取、打印或向模型传递凭据、完整页面或浏览器配置。

### 步骤 7：接入一个真实来源

- 工作：根据实际可访问条件选择首个来源；实现允许域名、搜索 URL、批量字段提取和规范链接；遇登录/验证码暂停来源并提示人工处理。
- 产物：src/platforms/ 下首个来源定义、离线页面夹具及提取测试。
- 依赖：步骤 2、6；真实浏览器操作须获得授权。
- 验收：夹具验证提取规则；主动真实冒烟获得具体视频链接；不无限滚动，不默认逐条补齐非必要字段，不绕过验证或执行平台写操作。

### 步骤 8：实现受限查找编排

- 工作：核心统一控制整轮生命周期与预算；生成有限查询、来源失败隔离、入库去重排序和稳定编号；保存推荐与交付确认分离；反馈同时用于下一轮查询和排序；记录安全来源状态、分段耗时、整轮墙钟耗时与模型调用次数。
- 产物：src/core/ 下编排实现及假来源集成测试。
- 依赖：步骤 3 的基础存储、步骤 4 的基础互斥实现和步骤 5～7；步骤 4 的整轮资源退出验收与本步骤一起完成，不形成“完整锁验收等待编排、编排又等待完整锁验收”的循环依赖。
- 验收：初始默认最多 6 个“平台＋查询词”组合、每组合 5～10 条、最多展示 10 条；单步建议 60 秒、每次最多重试 1 次、整轮建议 5 分钟；模型调用与输入 Token 有上限。最多两个来源并发，同来源查询串行，不在同标签页并发导航；不可用时退回串行。分支共享整轮截止时间；不足如实返回，取消后拒绝来源迟到的候选/推荐写入；子任务退出后收口批次并释放锁，清理失败不误报成功，异常批次不重放操作。

### 步骤 9：接入 Pi 薄适配

- 工作：按实际 Pi 文档、类型与示例注册查找、反馈、撤销入口；适配取消、编号展示及加载元数据；不复制业务逻辑。
- 产物：src/adapters/pi/ 实现、必要包元数据与宿主加载说明。
- 依赖：步骤 8及 Pi 实际接口确认；宿主安装/配置另需授权。
- 验收：Pi 实际加载成功；完成查找、交付、反馈、再次查找与撤销；定义实际工具/消息交付确认边界，覆盖失败/取消/重复确认，不声称用户实际看到或已看；引用不明确时确认批次；仅入口编译通过不能算宿主通过。

完成阶段 B 且通过对应真实冒烟，可交付明确标注范围的 **Pi 单来源试用版**。未完成外部搜索或 DSH 时，不宣称这些能力已支持。

## 4. 阶段 C：外部搜索与双宿主交付

### 步骤 10：增加外部搜索补充/降级

- 工作：分别确认宿主实际可用工具，适配为统一候选；记录发现通道与核验状态；接入共享预算，复用已有编排。
- 产物：src/adapters/ 下搜索适配及降级测试；不重复页面提取或排序逻辑。
- 依赖：步骤 8及对应宿主工具接口；可在 Pi 页面闭环后开展，不阻塞单来源交付。
- 验收：每轮最多 4 次补充搜索；链接核验与重试受整轮截止时间限制；摘要不冒充视频内容分析；主页/专题只作线索；未核验链接明确标记；无工具时明确禁用，不假定工具存在。

### 步骤 11：接入 DSH 薄适配

- 工作：核对实际版本、类型、注册入口和必要加载配置；复用核心与浏览器层；配置同一数据目录；搜索按实际能力接入。
- 产物：src/adapters/dsh/ 实现、必要加载配置与使用说明。
- 依赖：步骤 8、9；步骤 10按工具可用性接入，不作为页面闭环的硬依赖。
- 验收：DSH 实际加载并完成同一闭环；不新增第二套业务实现；未验证接口或通道明确标注。

### 步骤 12：双宿主最小冒烟与交付

- 工作：Pi 与 DSH 各查找一次；跨宿主读取同一数据库中的反馈并撤销；同时查找验证互斥；超时/取消后再次查找；记录实际分段耗时；更新状态和发布说明。
- 产物：关键冒烟结果摘要、README、docs/status.md 及相关验证说明，不保存完整工具日志或页面。
- 依赖：步骤 11。
- 验收：真实具体视频链接、来源状态、反馈持久化、撤销、跨进程互斥、调用预算和清理正常；目标一次 15～30 分钟冒烟，时间盒不能作为跳过阻断问题的理由。不要求固定候选数量或四个平台都可用，不编造性能或推荐效果结论。

## 5. 顺序与收口

```text
环境 → 数据契约 → SQLite → 跨进程锁 / 排序反馈
              └→ 浏览器执行层 → 首个来源
                         ↓
                      查找编排
                         ↓
                    Pi 最小闭环
                         ↓
              外部搜索 / DSH 薄适配
                         ↓
                    双宿主冒烟
```

按依赖顺序开发，共享接口变化先更新目标契约，再同步实现与调用端。测试随步骤加入，不最后集中补做。每次收口仅在项目状态维护进度与证据，区分静态检查、离线业务、真实宿主与来源冒烟；本批状态不替代整体计划状态。

失败时不削弱断言：来源故障可停用并保留其他来源；反馈异常先暂停偏好更新，保留原始反馈，修复后重算；未验证宿主不进入发布支持范围。不得未经授权安装插件或修改用户级设置。

## 6. 开始前待确认

1. 后续业务执行按状态文档的剩余项启动，先兼容性核对和生命周期/交付契约，再推进 Pi 单来源闭环；本次规范更新不代表这些能力已实现。
2. Pi、DSH 实际版本、加载方式及 Node 运行环境，尤其 node:sqlite 可用性。
3. 首个来源及专用浏览器运行条件；不假定四个平台均可访问。
4. 数据库与专用 profile 目录，两个宿主是否同机共用数据库及用户标识。
5. 各宿主已有外部搜索工具的真实接口与可用性。

权威计划中的 1～2 个工作日仅为基础环境可用时，共享核心与首个宿主试用版的目标估计。当前环境和宿主接口仍有未知，不作为双宿主工期承诺。其余来源、自定义平台配置与性能优化属于后续扩展，不属于当前规范优化范围。保存或更新计划本身不授权宿主安装及用户级配置修改。
