# 开发步骤拆分

本文将 [权威开发计划](development-plan.md) 拆分为可执行、可验证的小步骤，不替代其产品范围和运行边界。实际完成情况以 [项目状态](status.md) 为准，检查要求见 [验证规范](verification.md)。

**当前全部步骤待执行。保存计划不代表获得业务开发、依赖安装、浏览器操作或宿主安装授权。**

## 1. 规划依据与交付边界

保存时已只读核对源码及配置：TypeScript/ESM 骨架存在，core、browser、platforms 均为占位，Pi/DSH 是空入口。未安装项目依赖，无锁文件、实际测试或工具注册；当前 shell 的 PATH 找不到 node/npm。历史骨架构建结果不能作为业务或宿主兼容性证据。

分两次交付：

1. **Pi 单来源试用版**：兴趣 → 有限页面查找 → 去重排序 → 保存并展示 → 反馈与撤销 → 再找一轮。
2. **双宿主试用版**：DSH 薄适配，共享数据库、跨宿主反馈与查找互斥验证。

不等待四个平台全部可用，外部搜索可在页面闭环后接入。首版不开发自定义平台配置、独立 UI、定时任务或第二套浏览器后端；平台标识仍须可扩展。

## 2. 阶段 A：工程基础与共享核心

### 步骤 1：建立可复现开发环境

- 工作：确认 Node.js 22.13+（推荐 24）；安装开发依赖并保留锁文件；按需补充 Node 类型；建立离线测试脚本并同步说明。已有锁文件后才能使用 npm ci。
- 产物：package.json、锁文件、测试配置及首批真实测试；必要时调整 TypeScript 配置。
- 依赖：获得相应开发与依赖安装授权。
- 验收：项目内安装后 npm run typecheck、npm run build 通过；新增测试脚本实际运行断言；按验证规范检查打包内容，无数据库、profile 或凭据。

### 步骤 2：定义共享业务契约

- 工作：定义兴趣、候选视频、查询计划、批次、反馈、来源状态与运行预算；明确全局唯一批次 ID、编号绑定、取消和错误表达。
- 产物：src/core/ 下共享类型及契约测试；按需确定核心与浏览器、平台、宿主的小边界。
- 依赖：步骤 1。
- 验收：合成数据覆盖必填字段、未知字段和批次引用；新增平台不依赖固定四项枚举；接口无宿主耦合或循环依赖。

### 步骤 3：实现 SQLite 存储

- 工作：确认真实宿主中 node:sqlite 可用；实现兴趣、视频、批次、反馈、展示/已看记录的 schema、初始化、唯一键、事务与分步保存。
- 产物：src/core/ 下存储实现和临时数据库集成测试。
- 依赖：步骤 2。
- 验收：重启后可读取；重复视频不重复入库；事务失败回滚；批次结果顺序稳定；数据库不落到仓库。

### 步骤 4：实现跨进程查找锁

- 工作：同用户整轮查找互斥，忙时明确返回；正常结束、取消、失败释放；异常退出可有界恢复，不依赖单进程内存锁。
- 产物：src/core/ 下锁实现和多进程集成测试。
- 依赖：步骤 3。
- 验收：两个独立进程竞争，仅一个查找成功启动；取消和异常退出后可再次获取；等待有界，恢复不会误释放仍有效的其他任务锁。

### 步骤 5：实现兴趣、去重、排序与反馈

- 工作：链接规范化；按同平台 ID/链接去重；明确排除、已看过滤、作者分散和排序解释；反馈保存、撤销、事务内偏好重算。
- 产物：src/core/ 下业务模块与离线用例。
- 依赖：步骤 2、3。
- 验收：覆盖缺失元数据、硬条件未知、重复候选、歧义编号、反馈影响范围与撤销；“质量不好”默认只影响视频；无原因负反馈不自动降低整个主题；撤销后由有效反馈正确恢复偏好。

## 3. 阶段 B：页面发现与 Pi 最小闭环

### 步骤 6：实现受限浏览器执行层

- 工作：src/browser/ 封装 agent-browser CLI；专用会话/profile；校验参数，限制输出、超时、重试与调用量；接入取消、子进程生命周期和资源清理。
- 产物：CLI 执行封装、可控假执行器与离线测试。
- 依赖：步骤 1、2；实际 CLI 能力以实现时版本文档为准。
- 验收：假执行器验证参数、失败、超时、取消及清理；不用 shell 拼接不可信输入，不清理其他程序资源；不提取、打印或向模型传递凭据、完整页面或浏览器配置。

### 步骤 7：接入一个真实来源

- 工作：根据实际可访问条件选择首个来源；实现允许域名、搜索 URL、批量字段提取和规范链接；遇登录/验证码暂停来源并提示人工处理。
- 产物：src/platforms/ 下首个来源定义、离线页面夹具及提取测试。
- 依赖：步骤 2、6；真实浏览器操作须获得授权。
- 验收：夹具验证提取规则；主动真实冒烟获得具体视频链接；不无限滚动，不默认逐条补齐非必要字段，不绕过验证或执行平台写操作。

### 步骤 8：实现受限查找编排

- 工作：生成有限查询；来源失败隔离；入库、去重排序、保存展示顺序；反馈同时用于下一轮查询和排序；记录来源状态、分段耗时、整轮墙钟耗时与模型调用次数。
- 产物：src/core/ 下编排实现及假来源集成测试。
- 依赖：步骤 3～7。
- 验收：初始默认最多 6 个“平台＋查询词”组合、每组合 5～10 条、最多展示 10 条；单步建议 60 秒、每次最多重试 1 次、整轮建议 5 分钟；模型调用与输入 Token 有上限。最多两个来源并发，同来源查询串行，不在同标签页并发导航；不可用时退回串行。分支共享整轮截止时间；不足如实返回，取消/失败释放本任务资源与锁。

### 步骤 9：接入 Pi 薄适配

- 工作：按实际 Pi 文档、类型与示例注册查找、反馈、撤销入口；适配取消、编号展示及加载元数据；不复制业务逻辑。
- 产物：src/adapters/pi/ 实现、必要包元数据与宿主加载说明。
- 依赖：步骤 8及 Pi 实际接口确认；宿主安装/配置另需授权。
- 验收：Pi 实际加载成功；完成查找、展示、反馈、再次查找与撤销；引用不明确时确认批次；仅入口编译通过不能算宿主通过。

完成阶段 B 且通过对应真实冒烟，可交付明确标注范围的 **Pi 单来源试用版**。未完成外部搜索或 DSH 时，不宣称这些能力已支持。

## 4. 阶段 C：外部搜索与双宿主交付

### 步骤 10：增加外部搜索补充/降级

- 工作：分别确认宿主实际可用工具，适配为统一候选；记录发现通道与核验状态；接入共享预算，复用已有编排。
- 产物：src/adapters/ 下搜索适配及降级测试；不重复页面提取或排序逻辑。
- 依赖：步骤 8及对应宿主工具接口；可在 Pi 页面闭环后开展，不阻塞单来源交付。
- 验收：每轮最多 4 次补充搜索；链接核验与重试受整轮截止时间限制；摘要不冒充视频内容分析；主页/专题只作线索；未核验链接明确标记；无工具时明确禁用，不假定工具存在。

### 步骤 11：接入 DSH 薄适配

- 工作：核对实际版本、类型、注册入口和必要加载配置；复用核心与浏览器层；配置同一数据目录；搜索按实际能力接入。
- 产物：src/adapters/dsh/ 实现、必要加载配置与使用说明。
- 依赖：步骤 8、9；步骤 10按工具可用性接入，不作为页面闭环的硬依赖。
- 验收：DSH 实际加载并完成同一闭环；不新增第二套业务实现；未验证接口或通道明确标注。

### 步骤 12：双宿主最小冒烟与交付

- 工作：Pi 与 DSH 各查找一次；跨宿主读取同一数据库中的反馈并撤销；同时查找验证互斥；超时/取消后再次查找；记录实际分段耗时；更新状态和发布说明。
- 产物：关键冒烟结果摘要、README、docs/status.md 及相关验证说明，不保存完整工具日志或页面。
- 依赖：步骤 11。
- 验收：真实具体视频链接、来源状态、反馈持久化、撤销、跨进程互斥、调用预算和清理正常；目标一次 15～30 分钟冒烟，时间盒不能作为跳过阻断问题的理由。不要求固定候选数量或四个平台都可用，不编造性能或推荐效果结论。

## 5. 依赖与协作

```text
环境 → 数据契约 → SQLite → 跨进程锁 / 排序反馈
              └→ 浏览器执行层 → 首个来源
                         ↓
                      查找编排
                         ↓
                    Pi 最小闭环
                         ↓
              外部搜索 / DSH 薄适配
                         ↓
                    双宿主冒烟
```

共享契约确定后，核心与浏览器/平台模块可按文件所有权并行；共享接口和配置由单一负责人协调，不同时写同一文件。测试随各步骤加入，不最后集中补做。每次实际交付更新项目状态，区分静态检查、离线业务测试与真实冒烟。

失败时不削弱断言：来源故障可停用并保留其他来源；反馈异常先暂停偏好更新，保留原始反馈，修复后重算；未验证宿主不进入发布支持范围。不得未经授权安装插件或修改用户级设置。

## 6. 开始前待确认

1. 下一轮授权范围：建议先执行步骤 1～2，再推进 Pi 单来源闭环。
2. Pi、DSH 实际版本、加载方式及 Node 运行环境，尤其 node:sqlite 可用性。
3. 首个来源及专用浏览器运行条件；不假定四个平台均可访问。
4. 数据库与专用 profile 目录，两个宿主是否同机共用数据库及用户标识。
5. 各宿主已有外部搜索工具的真实接口与可用性。

权威计划中的 1～2 个工作日仅为基础环境可用时，共享核心与首个宿主试用版的目标估计。当前环境和宿主接口仍有未知，不作为双宿主工期承诺。其余来源、自定义平台配置与性能优化属于后续扩展，不因本文保存而自动获准实施。
