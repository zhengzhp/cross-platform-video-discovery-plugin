# 架构与模块契约

本文是目标架构与实现约束，不代表全部能力已实现。实际模块、限制及验证证据统一见 [项目状态](status.md)；产品范围见 [开发计划](development-plan.md)，实施依赖见 [开发步骤](development-steps.md)。不新增通用任务框架或浏览器后端抽象。

## 1. 分层与依赖

```text
Pi / DSH 薄适配：注册、输入转换、取消、输出交付
                  ↓
core 编排：兴趣、预算、整轮任务、去重排序、存储与反馈
                  ↓ 通过小接口调用
platforms：域名、搜索 URL、视频识别、字段提取
                  ↓
browser：受限 agent-browser CLI、会话和子进程清理
```

- 共享数据契约放在 core 的轻量类型模块，不依赖宿主、浏览器实现或数据库初始化。platforms/browser 可导入这些类型，不从 core 总入口反向加载存储等运行时模块。
- adapters 负责组装核心、来源与浏览器并传入依赖；core 编排通过实际需要的小接口调用来源，不导入宿主 SDK 或具体平台注册列表。
- platforms 调用 browser；browser 不反向导入 platforms、adapters 或业务存储。core 存储不启动浏览器、不调用宿主、不在模块导入时打开数据库。
- 同一站点规则仅实现一次；新增来源不复制宿主逻辑，不把首批四个平台写成不可扩展枚举。暂不实现用户配置加载或远程插件。

## 2. 模块契约与责任

以下是行为契约；后续编码时映射到最小接口和测试，不要求现在补占位框架。

| 边界 | 输入 / 输出 | 负责 | 不负责 / 禁止 |
| --- | --- | --- | --- |
| adapters → core | 已校验用户请求、用户标识、取消信号；批次 ID、编号结果、来源状态 | 宿主 schema 校验、参数转换、结果交付及确认 | 不复制排序/反馈；查找不绕过编排直调浏览器或写数据库 |
| core → 来源接口 | 平台与查询、共享截止时间、剩余预算、任务取消；有界候选及结构化来源状态 | 调度、全局预算、失败隔离、查询级有限重试 | 不读 DOM；不信任来源自报“授权”或无限等待 |
| platforms → browser | 已校验允许域名的 URL、固定只读提取操作、任务上下文；有界执行结果 | 域名/跳转检查、具体视频识别、ID/链接规范化、字段提取、登录/验证码分类 | 不写业务数据库，不拥有整轮锁，不执行网页提供的命令 |
| browser → platforms | 紧凑结构化输出或安全错误码 | 无 shell 拼接的 CLI 参数、单步超时/输出上限、取消、资源清理与退出确认 | 不判定兴趣匹配或推荐质量；不输出原始页面/凭据；不自行增加重试 |
| core → 存储 | 规范候选、批次、反馈、交付确认 | 持久化校验、唯一性、事务、稳定编号和有效反馈重算 | 不将保存结果自动记为已交付或已看，不在事务内等待浏览器/模型/用户 |

外部搜索由 adapters 调用实际可用的宿主工具并提供统一候选，受核心预算约束。搜索候选须经过同样的域名与具体视频判断，不能把摘要或主页当成视频分析结果。工具缺失时明确禁用该通道，不假定任意宿主都能调用同一扩展。

### 校验、核验与错误

- 网页字段始终视为数据。platforms 先做站点相关校验，core 再做候选长度、URL、字段和批次数量等通用校验；来源不得用额外字段扩大任务能力。
- “在结果页观察到视频链接”不等于打开详情验证，更不等于内容分析。核验状态必须携带依据，不能由模型或宿主展示层任意升级；未核验、未知时长/作者/深度如实标记。
- 来源状态区分成功、失败和需人工处理的暂停；错误区分取消、超时、登录/验证码、工具不可用、提取/校验失败与存储故障。后续将分类映射到稳定安全码，不把 CLI stderr 或网页文本直接当作日志文案。
- 查询级重试只由 core 编排决定且消耗同一预算；browser/platforms 不叠加重试。登录/验证码不重试绕过；存储故障中止整轮，来源故障可以独立降级。

## 3. 整轮生命周期与资源所有者

**core 编排是整轮生命周期的唯一控制方。** adapters 发起/取消，browser 管理本任务创建的子进程、标签页/会话；存储管理短事务与锁所有者令牌。

```text
校验请求、运行条件与预算
  → 获取同用户查找锁（忙时返回，不无限排队）
  → 创建持久化批次
  → 按来源执行查询，分步保存候选与推荐结果
  → 停止接受新任务，取消/等待所有子任务退出
  → 收口批次为完成 / 失败 / 取消
  → 释放查找锁
  → 返回结果，宿主交付成功后单独确认
```

以上所有异常路径均须收尾：创建批次失败也释放已获取的锁；终态保存失败仍清理本任务资源，并明确报告存储失败。查找锁不跨越用户等待或反馈操作，交付确认是独立短事务，不启动新的查找。

### 预算与取消

- 初始参数来自开发计划；编排为每轮建立绝对截止时间、取消信号与调用计数。每个分支/重试/降级消耗同一预算，单步时限不超过剩余整轮时间。常量或接口定义不等于已执行保护。
- 最多两个来源并发，同来源查询串行，来源间独立导航资源；能力不确定时先串行。取消后停止调度并拒绝来源迟到的候选/推荐写入，核心仍负责终态收口；任务/批次标识用于区分已结束任务。
- 浏览器层负责停止并等待本任务子进程退出、关闭本任务拥有的页面/会话；可复用专用 profile 的持久文件不因取消而删除，不处理外部资源。
- 清理使用独立的有限收尾预算，不重复使用已中止的工作信号。不因为截止时间到了就假设已清理：无法确认退出时报告清理故障，保留安全的互斥状态并阻止冲突新任务，不提前释放有效锁或无限等待。
- 进程崩溃后的恢复只确认旧任务失效、处理本任务残留并收口异常批次，不重放页面操作或实现复杂断点续跑。PID 复用、挂起活进程与资源失联的恢复策略须实现并测试后才能声明完整锁验收通过。

## 4. 保存、交付与已看语义

| 事件 | 含义 | 对下一轮的影响 |
| --- | --- | --- |
| 候选保存 | 获取到元数据，可能未选中 | 按 ID/规范链接去重，不当作已推荐 |
| 推荐结果保存 | 持久化批次顺序与编号 | 保证引用稳定，不当作交付成功 |
| 交付确认 | 宿主按实际可确认的工具/消息交付边界接受本批结果 | 默认避免再次推荐已交付结果；不能声称用户实际看到或观看 |
| 用户已看反馈 | 用户显式标记某批次视频已看 | 已看过滤，可撤销；历史/明确重新推荐请求可例外 |

- 完成查找与完成交付是不同事件，不能把展示失败变成来源失败。交付失败或取消时，不用仅保存的结果过滤下一轮；结果与批次仍保留供恢复引用，不自动重放查找。
- 交付确认以用户、批次和明确结果集合幂等写入，不重排编号。部分交付只能确认实际交付部分；没有可靠确认能力时保留“交付未确认”，不假造确认。
- 宿主接入前须定义它能确认的交付边界，并以离线故障用例验证“保存成功、交付失败”不误标已看/已交付。当前存储实现与目标语义的差距见项目状态，本文不是已完成迁移声明。

## 5. 运行兼容性与演进边界

- 在继续来源与宿主实现前，先只读核对目标 Pi/DSH 的版本、加载方式、工具返回/取消接口和实际 Node 环境，尤其 node:sqlite。实际加载或安装按任务授权执行；未验证项记录在状态中，不用本机测试代替宿主检查。
- agent-browser 参数、专用 profile 与子进程能力按实现时版本确认；域名校验同时考虑导航后的目标，不对登录/验证码作绕过。
- 数据目录由调用方显式配置到仓库外私有位置；两个宿主共用数据库时必须使用相同用户标识和同机锁语义，不承诺跨机器共享文件或同步。
- schema 或交付语义变更先定义旧数据兼容/迁移策略，不把旧“已保存”记录无证据升级成“已交付”；反馈原始记录保留，偏好可重算。拒绝不支持的新 schema，失败不破坏旧数据。
- 只增加当前闭环需要的小接口；自定义来源、多后端、独立 UI、复杂队列与监控均不作为本次规范优化的实施内容。
