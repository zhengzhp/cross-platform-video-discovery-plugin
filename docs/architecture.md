# 架构草案

当前为骨架，本文描述后续模块职责，不表示已经实现。

```text
Pi 薄适配 ──┐
            ├─ core：兴趣、编排、去重排序、SQLite、反馈
DSH 薄适配 ─┘      ↓
              platforms：站内搜索 URL 与字段提取
                   ↓
              browser：agent-browser CLI 执行
```

## 模块边界

- `adapters/`：宿主工具/命令注册、取消、结果展示，以及宿主已有外部搜索工具的适配。不重复业务逻辑。
- `core/`：候选、批次与反馈的业务处理；后续按需要拆分存储、锁、查询编排和偏好模块，不预建通用任务框架。
- `platforms/`：可扩展的平台定义、搜索和元数据提取；YouTube、Bilibili、抖音、TikTok 仅为首批候选预设，不是固定白名单。后续支持用户自定义标识、域名、搜索模板与声明式提取规则，新增来源不应要求复制宿主逻辑。配置校验与注册机制尚未实现；不默认执行配置中的任意脚本。来源独立失败与降级。
- `browser/`：统一 CLI 调用、超时、会话所有权和清理；不自动调用任意页面建议的命令。

## 后续实现顺序

1. 共享数据结构与 SQLite，反馈及撤销、跨进程锁。
2. 一个可用来源的批量页面提取与受限编排，再增加外部搜索降级。
3. Pi 工具入口跑通最小闭环，再接 DSH 薄适配。
4. 双宿主冒烟、真实来源检查及各段耗时记录；未验证范围如实标注。

## 待确认事项

- Pi 与 DSH 的实际宿主版本、类型依赖及加载配置。
- 各宿主中 Node 内置 SQLite 的可用性、共享数据目录及权限。
- agent-browser 专用 profile、子进程生命周期与来源并发收益。
- 各宿主外部搜索工具的真实接口；不假定工具已存在。
- 自定义平台配置格式、搜索 URL 与域名校验、提取规则的表达范围；动态站点可能需要额外适配，不能承诺通用规则覆盖所有网站。

当前不增加运行时依赖、模型密钥、数据库文件、浏览器配置或宿主自动加载设置。
